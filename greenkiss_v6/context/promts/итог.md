Category (категория)

id: уникальный идентификатор
name: имя на русском (например, «Женщинам». Пока не будем делать перевод на несколько языков одного твоара. Таково даже на амазон нет)
description: описание категории, нужно ограмничить количсевто символов на клиенет и сервер (придумай нормальное)
slug: слаг для URL (автогенерация из русского: «Женщинам → zhenshchinam», уникален внутри одного родителя)
full_path: полный путь для роутинга (например, women/leggings). Делает открытие страницы по URL мгновенным
parent_id: ссылка на родителя (null для корня)
image_id: основная картинка (страница категории, админка будет автоматически сжимать и переводить в webp, сама база будет хранить ссылку на S3)
seo-поля (минимально необходимое):
meta_title (по умолчанию = name)
meta_description (Обязательно)
og_title (по умолчанию = name)
og_description (Обязательно)
og_type (обычно website)
canonical_url (собирается автоматически из домена + full_path)
meta_robots (например, index,follow (выбери правильный))
status: draft | active | hidden (удобно скрывать разделы без удаления)
sort_order: число для ручной сортировки в меню (это зачем нужно?)
level: глубина в дереве (0 для корня) — удобно и быстро для интерфейса
created_at / updated_at

CategoryClosure (карта родства)
ancestor_id: предок
descendant_id: потомок
depth: расстояние (0 — это категория сама себе предок)
Ограничение уникальности: (ancestor_id, descendant_id)
Индексы: по ancestor_id и по descendant_id (для быстрых запросов «вверх» и «вниз» по дереву)
Что это дает на практике:

Быстрая выборка всех предков для хлебных крошек.
Быстрая выборка всех потомков (включая вложенные уровни) — важно для фильтрации товаров по целой ветке.
Быстрый пересчет «агрегатов» вверх по дереву (количество товаров/брендов и т. д.).
