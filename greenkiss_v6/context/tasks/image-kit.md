### Общие цели
- **Максимально лёгкий клиентский UI-набор** для работы с изображениями (кроп, ресайз, смена расширения, сжатие, сравнение).
- **Всё в браузере, без серверной нагрузки**.
- **Стек:** Next.js 16.0.3 (App Router), TypeScript (без any), react-image-crop (**не react-easy-crop**), shadcn-ui, TailwindCSS.
- **Стиль:** shadcn-ui + Tailwind.  
- **Строгая SRP:** каждый компонент решает только свою задачу!  
- **Язык интерфейса:** русский (RU) по умолчанию. Все ошибки для разработчика на англйиском, для клиента в интерфейсе на русском.

---

### Термины
- **Формат (aspect):** пропорция (1:1, 3:4, 4:3, 16:9, 9:16).
- **Разрешение (size):** ширина и высота в пикселях (например, 1200×300).
- **Расширение (format):** png | webp | jpg/jpeg (`jpg` и `jpeg` = `image/jpeg`, расширение файла = `.jpg`).
- **Вес файла:** показывать в KiB/MB.
- **Выход:** итоговые файлы на клиенте.

---

### File Structure

Библиотека располагается строго по пути:

```
src/shared/ui/image-kit/
  index.ts                   # реэкспорт публичного API
  _image-input/              # ввод/кроп/валидация (ImageInput)
  _image-compare/            # сравнение “до/после” (ImageCompare)
  _image-editor/             # пакетный редактор/настройщик (ImageEditor)
  _lib/                      # утилиты, типы, валидации
  _ui/                       # мелкие обёртки поверх shadcn (если нужны)
```
**Именование файлов:** kebab-case, SRP на каждый компонент/утилиту/тип.

### Общие UI и API правила
- **Импорт компонентов shadcn-ui только через:** `@/shared/ui/kit/COMPONENT_NAME`
- **Диалоги только через `<AlertDialog />` (shadcn-ui)**:
    - Ширина: 90vw, max-width: 1024px.
    - Закрытие _только_ по кнопке (“Готово”, “Сохранить”, “Закрыть”).  
    - НЕ закрывать по ESC/overlay.
- **Кнопки подтверждения:** дизейбл во время обработки, показывать лоадер (Tailwind spinner), при обработке — серый оверлей и текст “Обработка…” на картинках.
- **Все контролы должны иметь label/aria.**
- **Все иконки должны иметь атрибут aria-hidden="true", а кнопки без текста arai-label="Краткое описание на русском"**
- **RU-локализация:** только понятные пользователю подписи и кнопки (“Готово”, “Удалить”, “Сохранить”, “Сравнить”, “Растянуть мелкие”, “Формат”, “Размер”, “Расширение” и т.д.).
- **Маленькие изображения:**  
    - По умолчанию отображаются в _реальном масштабе_.  
    - Есть переключатель "Растянуть мелкие" (лупа) — тогда картинки-”малыши” занимают всю доступную область секции (вертикалки тянутся по ширине, горизонталки — по высоте секции, не выходя за рамки контейнера).
- **Обязательные валидации:** aspect, мин. ширина/высота, мин/макс-вес, разрешенные расширения, соответствие aspect при targetSize.

## **1. ImageInput (отвечает только за загрузку с формат-контролем через кроп)**

### **Единственная ответственность**
- Загрузить 1 или несколько картинок (выбирает пользователь или parent-компонент через props).
- Проверить (через кроп) соответствие формата aspect (3:4, 16:9 и т.д.)
- Вернуть итоговые ProcessedImage через onSubmit.

### **Логика/UX**
1. **Триггер на клиенте:** пользователь выбирает 1-5 файлов (multiple зависит от props, но максимум — всегда 5).
2. **AlertDialog:**  
    - Вверху — рамка `border-primary` с пропорциями формата, внутри — подпись (“3x4”, “16x9” и т.д.).
    - Для каждой картинки — отдельная секция, визуально разделены.
    - Картинки:
        - **Меньше секции:** центрируются, занимают свои пиксели.
        - “Растянуть мелкие” — кнопка; такие тянутся (вертикальные — по ширине секции, горизонтальные — по высоте секции), но не вылетают за пределы рамки.
        - **Больше или равно секции:** горизонтальные — высота равна высоте секции. Вертикальные высотой не больше ширины секции.
    - **Кроп:**  
        - Сразу в верхнем левом углу изображения и до конца самой маленькой стороны (высоты или ширины), всегда фиксированный формат (aspect).
    - **Готово:** дизейблится во время обработки, появляется оверлей “Обработка…” — как в референсе.
    - Условия открытия: нельзя закрыть диалог иначе как по “Готово/Отмена” (alertDialog).
3. **Валидация:** aspect (кроп контролирует, но добавить можно любой), разрешенные расширения через props.

### **Props**
```ts
export type ImageInputProps = {
  open: boolean;
  onOpenChange?: (next: boolean) => void;
  multiple?: boolean; // по умолчанию false
  allowedExtensions?: AllowedExtensions; // по умолчанию все true (png, webp, jpg/jpeg)
  aspect: AspectRatio;
  bannerSizePresets?: SizePx; // Если задан, то вместо аспекта используется соотношение баннера
  onSubmit: (images: ProcessedImage[]) => void;
  onError?: (error: Error) => void;
};
```
**ВАЖНО:**  
- maxFiles=5 жестко, не меняется.
- Обработка/валидация массива (сколько именно файлов валидировать, решает родитель).
- Никакой другой логики! Только: choose → crop → validate → return.

## **2. ImageCompare**  

Назначение
- Визуально сравнить две версии одной картинки (до/после) с помощью “шторки” (vertical handle).
- Отображается в обычном диалоге <Dialog /> 90vw ширины или максимальную 1024px. Диалог контент без panding как и сам диалог, чтобы картинки щанималю всю доступную площадь. Но заголовок что это сравнение двух изображение нужен.

Этот компонент для удобства, поэтому закрытие диалога не на что не влияет. Пропсами принимает левое и правое изображения. Левое с левой стороны от шторки, а правая с правой стороны от шторки. Картинка растягивается на min(ширина диалога, ширина картинки). 

Поведение и UX
- Определяет формат (aspect) обоих изображений. Если не совпадают — показываем информативную ошибку: “Формат левой: X, правой: Y. Форматы должны совпадать.”
- В диалоге накладываем изображения друг на друга:
  - Разделительная полоса с ползунком по центру.
  - Можно двигать горизонтально (по ширине) — слева видна левая картинка, справа — правая.
- По умолчанию просто “Закрыть”.

Props
```tsx
export type ImageCompareProps = {
  open: boolean;
  onOpenChange?: (next: boolean) => void;

  left: Blob | File | string;   // Blob/File или dataURL/URL
  right: Blob | File | string;

  onError?: (error: Error) => void;
};
```

Компонент 3: ImageEditor (пакетный редактор/настройщик)
Назначение
- Управляет набором изображений: единый формат (aspect), единый размер (width/height), единое расширение, единый вес в пределах (min/max). Может сжимать, удалять, сравнивать до/после.
- Вверху — общая секция настроек. Ниже — секции по каждой картинке.

Поведение и UX
- Общая секция:
  - Формат (aspect), просто показывает aspect картинок. Если картинки разных aspect то появляется select аспектов. Все остальное дизеблится и загаратеся красным, пока не выберется аспект. Выбор аспекта запускает кроп (ImageInput (поэтому кроп нужно вынести в отдельный компонентЮ, разделив с ImageInput, но чтобы его использвоать как в ImageInput так и в ImageEditor)). После нормализации aspect, select исчезает.
  - Размер (width/height) — связаны с aspect; изменение одной стороны пересчитывает другую.
  - Расширение (опционален, передается пропсом, если не пердали то показывает все расширения у загруженных картинок, если указан. То сразу меняет расширенеи на указанные, в этот момент все дизеблетися и показывается оверлей “Обработка…”. Ну и показывает выбранное Расширение)

- Жёсткие бизнес-правила:
  - Все изображения должны иметь один aspect. Если сейчас разные — общие и локальные секции подсвечиваются красным. Кнопки/селекты дизейблятся, кроме селекта выбора формата. После выбора формата — все несоответствующие помечаются с предложением удалить или изменить через кроп.
  - Все изображения должны иметь одинаковый размер (width/height). Если меньше, то предложение только удалить такие картинки, если больше, то автоматически меняется, также все дизеблится и атк далее, идет обработка. Передается пропсом и является обязательным знаечнием (валидируется на соовтествие aspect).
  - Любое изменение, требующее сжатия, блокирует кнопки, показывает лоадер и оверлеи “Обработка…” на всех (чтобы избежать параллельных конфликтов). В каждой секции картинки есть кнопка сравнить (если было сжатие ее можно нажать), кнопка сжатия, при нажатии идет обработка, в конце обработки запускается сравнение. Также выбрать до сжатия или после сжатия (любая из них стирает другую). Также идет подсветка стоит ли еще сжать или картинка уже весит нормально
- В каждой карточке изображения:
  - Действия: Удалить до сжатия, удалить после сжатия, Сжать (при повторном сжатие, прошлая удаляется, оставляется сжатая и добавляется новая повторно сжатая), Сравнить (активно, если есть предыдущая версия для сравнения).
- Валидации веса:
  - minBytes/maxBytes — валидировать каждую картинку. maxBytes — предлагают сжимать пока не станет нормальной или удалить;

Props
```tsx
export type ImageEditorProps = {
  open: boolean;
  onOpenChange?: (next: boolean) => void;

  images: Array<Blob | File | string>; // входные изображения (если пусто — компонент не показывается)

  requiredFormat: OutputFormat;       // фиксированное расширение (если задано — селект расширения недоступен)
  allowedExtensions?: AllowedExtensions; // по умолчанию все разрешены

  requiredAspect: AspectRatio;        // фиксированный формат сторон (если задан — селект аспекта скрыт)
  requiredSize: SizePx;               // требует обязательного aspect (TS ограничением и рантайм-валидатором)

  maxBytes: number;                   // по умолчанию 1_048_576 (1 MiB)
  minBytes: number;                   // по умолчанию 256

  onSubmit: (images: ProcessedImage[]) => void; // когда нет ошибок и нажата нижняя кнопка “Сохранить”
  onError?: (error: Error) => void;
};
```

Алгоритмы обработки (общие)
- Загрузка изображения: через File/Blob/URL/dataURL -> HTMLImageElement, через _lib/image-load.ts.
- Кроп:
  - Начальная область: x=0, y=0, size=min(width,height), aspect если задан — вписать в min-сторону.
  - Пользователь может двигать и масштабировать внутри react-image-crop с фиксированным aspect (если задан).
  - Итог — рисуем crop в Canvas (_lib/crop.ts).
- Ресайз:
  - Если targetSize задан — билinear/quality пресет через canvas drawImage (бережно к пропорциям).
  - Валидация: если targetSize не соответствует aspect — в dev выбрасывать Error (раньше рендера).
- Конвертация/сжатие:
  - Выходной тип: targetFormat (если не задан — сохраняем исходный mime или нормализуем jpeg->jpg).
  - Сжатие для webp/jpeg: бинарный поиск/ступенчатое снижение качества (например 0.92 -> 0.85 -> 0.75 -> …) до <= maxBytes.
  - PNG: без потерь. Если нужно меньше веса — предложить конвертировать в webp/jpg.
- Возврат результата:
  - Массив ProcessedImage. File содержит подходящее имя (с сохранением базового имени и заменой расширения).
  - Дополнительно можно вернуть dataUrl (опционально).

Доступность и управление
- Все контролы имеют label/aria-атрибуты.
- Диалоги управляются пропсами open/onOpenChange.
- Закрытие только явно через кнопки.

Тексты (RU, примеры)
- Готово, Сохранить, Отмена, Закрыть, Обработка…, Растянуть мелкие, Формат, Размер, Расширение, Удалить, Сжать, Сравнить, Ошибка формата: Левое X, Правое Y. Форматы должны совпадать.
