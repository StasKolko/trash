В scripts/code-map/ создать модуль для сбора метрик/рефактора кода.

Есть в корне index.ts для запуска основной функции куда передаю ignoreExtenstions без точки и rootDir

Что-то типа:

```ts
const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

codeMap({
  rootDir: resolve(__dirname, '../../'),
  ignoredExtensions: ['svg', 'png', 'webp', 'jpg', 'jpeg']
})
```

А также config.ts типа:

```ts
export type Config = {
  [key: string]: Config | ConfigStatus;
};

type ConfigStatus = 'ignore' | 'ok';
```

В нем значения это имя файла или папки:

```ts
export const config: Config = {
  'node_modules': 'ignore',
  'docker-compose.yml': "ignore",
  "src": {
    'shared': 'ignore',
    'app': 'ok'
  }
}
```

Где я указываю что игнорить, а что точно ok. То есть если у папки ignore или ok значит все содержание папки такое. А вот в кеше так нельзя, нужна чтобы каждого файла было значение ok или error, без папок.

Отдельно сделай файл кеша или как-то по другому назови его. Он нужен для рабоыт прогрммы и содержит результат прошлой работы программы.

Логика:

Всегдя кеш, конфиг сохраняются, а сообщение о результате в консоль выводятся в виде:
Папки в алфавитном порядке
Файлы в алфавитном порядке

Код пробегает по всем файлам и папкам рекурсивно. Если папка или файл ignore в конфге, то она удаляется из кеша (если была). Если есть пути в кофниге, которых при текущем обходе нет, значит их удалить из конфига. Также и несущесвтующие пути из кеша тоже удалить из него. Если при обходе хеш файла отличается от хеша в кеше, то такой файл помечается как error в кеше. Если файл новые и под него не был в кеше создан ключ, то он сразу помечается как error и под него создается хеш. Если в конфиге файл ok, а в кеше как error, то смотрим поменялся ли хеш. Если хеш не поменялся, то меняем в кеше на ок (значит что пользователь осознано в конфиге его как ок пометил). Если в конфиге папка помечена как ок, то в кеше проверяем хеш всех файлов внутри этой папки, если у всех файлов не поменялся хеш, то значит все файлы внутри этой папки в кеше становятся ok.

В конце работы программы записывается новый конифг. В нем только файлы и папки ok и ignore (папка может быть ok только если все внутри файла нее в кеше тоже ok, получается токое колапс для конфига). Также в консоль выводятся:

Количество найденных файлов
Количество error файлов
Количество ok файлов
Процент рефакторинга (ok файлы деленные на все файлы и умноженные на 100)

 все error файлы и папки (также делаем колапс папок, если все внутри error).
